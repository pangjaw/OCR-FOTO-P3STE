### 7. Perbaikan Koneksi SSE & Sinkronisasi Status Idle (Fix Freeze on Inactive Tab)
- **Gejala**: Ketika web app didiamkan lama (tab browser idle/tidak aktif), koneksi streaming log terputus diam-diam oleh browser/TCP timeout. Saat user menekan tombol jalankan step (misal `Step 5 Time`), log hanya menampilkan baris lokal `>>> Command sent to run step...` dan status badge di kanan atas tetap `System Ready`, meskipun proses Python di latar belakang sebenarnya berjalan normal.
- **Penyebab**:
  1. Ketiadaan *heartbeat ping* berkala pada koneksi SSE dari server, sehingga TCP socket ditutup diam-diam oleh OS/browser saat tidak ada data mengalir.
  2. `EventSource` di frontend tidak memiliki mekanisme *auto-reconnect*, *error recovery*, dan listener saat tab aktif kembali (`visibilitychange`).
  3. Ketiadaan endpoint `/api/status` untuk sinkronisasi status latar belakang secara berkala.
- **Solusi & Perbaikan**:
  1. Di [server.js](file:///C:/Users/dikarm/Documents/Server/OCR-FOTO-P3STE/server.js):
     - Ditambahkan heartbeat ping `: ping\n\n` otomatis setiap 15 detik untuk menjaga TCP socket tetap hidup (*keep-alive*).
     - Ditambahkan endpoint `GET /api/status` (`is_running`, `step`, `active_clients`).
     - Ditambahkan socket options `setKeepAlive(true)`, `setNoDelay(true)`, dan filter pembersihan client yang disconnect.
  2. Di [templates/index.html](file:///C:/Users/dikarm/Documents/Server/OCR-FOTO-P3STE/templates/index.html):
     - `initSSE()` dilengkapi *auto-reconnect* jika koneksi putus (retry setiap 3 detik).
     - Ditambahkan listener `document.visibilitychange`: saat user kembali membuka tab browser, koneksi SSE otomatis dipulihkan seketika.
     - Fungsi `runStep()` melakukan *optimistic UI update* ke status `Running <step>...` secara instan, memastikan SSE aktif, dan mencocokkan status ke `/api/status`.
     - Ditambahkan polling cadangan `checkPipelineStatus` setiap 8 detik sebagai pengaman ganda.

### 9. Analisis & Peningkatan Detail Log Error `export_pdf_foto.py` (Fix Exit Code 1)
- **Gejala Masalah**: Pipeline berhenti pada Step 1 dengan pesan `❌ export_pdf_foto.py exited with code 1` tanpa keterangan detail yang menjelaskan penyebab error kepada pengguna.
- **Penyebab Utama (Root Cause)**:
  1. **Logika Exit Code False-Negative**: Pada baris akhir `main()`, script mengeksekusi `return 0 if total > 0 else 1`. Jika seluruh foto di `03_photos_export` sudah ada atau dilewati (`OVERWRITE=0`), nilai `total` foto baru adalah `0`, sehingga Python mengembalikan exit code **`1`** (dianggap gagal padahal tidak ada file error).
  2. **Error Swallowing / Minim Detail**: Blok penangkap error hanya mencetak `[ERROR] Gagal memproses {file}: {exc}` satu baris tanpa jenis error, nomor baris, atau traceback. Jika terjadi error di tengah 380+ file, pesan tersebut tenggelam di terminal.
  3. **Output Buffering pada Server**: Node.js menjalankan Python tanpa argumen unbuffered (`-u`) dan tanpa `PYTHONUNBUFFERED=1`, menyebabkan log tertahan di buffer dan tidak muncul secara langsung (real-time) di antarmuka web.
- **Perbaikan yang Dilakukan**:
  1. Di [scripts/export_pdf_foto.py](file:///C:/Users/dikarm/Documents/Server/OCR-FOTO-P3STE/scripts/export_pdf_foto.py) & [export_pdf_foto.py](file:///C:/Users/dikarm/Documents/Server/OCR-FOTO-P3STE/export_pdf_foto.py):
     - Memperbaiki logika exit code: return `0` jika `len(failed_files) == 0` (tetap sukses walau tidak ada foto baru yang perlu diekspor ulang).
     - Menambahkan penangkapan error terperinci (`error_type`, `error_msg`, baris pemanggil, dan traceback).
     - Menampilkan kotak ringkasan komprehensif di akhir proses (*Total PDF, Sukses, Skip, Gagal*).
     - Jika ada file gagal, otomatis menampilkan daftar nomor urut file bermasalah dan menyimpan laporan terstruktur ke `logs/export_errors.json`.
  2. Di [server.js](file:///C:/Users/dikarm/Documents/Server/OCR-FOTO-P3STE/server.js):
     - Menambahkan flag unbuffered (`-u`), `PYTHONUNBUFFERED: '1'`, dan `PYTHONIOENCODING: 'utf-8'` agar seluruh pesan dan log mengalir seketika ke antarmuka web tanpa terpotong atau tertahan buffer.
     - Menambahkan banner ringkasan kegagalan jika script Python keluar dengan kode kesalahan (`code !== 0`), menampilkan cuplikan baris error terakhir kepada user.
