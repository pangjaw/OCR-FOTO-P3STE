### 2. Global Scheduler Date Overflow & Per-Date State Tracking
- **Root Cause Identified**:
  - `scheduler.py` previously sorted PDF files alphabetically by filename rather than by target date, causing date switching between PDF files during processing.
  - Overflow logic previously shifted dates (`pdf_date + 1 day`) when work passed 18:00, causing mid-day clock resets back to 07:00 and duplicate timestamps across different assets on the same date.
- **Key Algorithmic Fixes in `scheduler.py`**:
  - `_pdf_date_key()`: Added sorting key to order PDF target files strictly by target date before scheduling.
  - `date_state`: Implemented independent per-date tracking dictionary `date_state[date_str]` = `{"tim": tim, "clock": clock}` so each target date maintains its own isolated sequential time allocation and team overflow without interfering with other dates.
  - **Asset Deduplication**: Deduplicated entries per date `(btp, category, identifier, date_str)` so each physical asset on a target date receives exactly 1 official schedule slot.
  - **No Date Shifting**: Removed date-shifting on overflow so timestamps remain strictly on the target date (allocating Tim 1, Tim 2, Tim 3 dynamically on that date as needed).
- **Verification Results**:
  - Global schedule total: Tepat **398 aset unik** (100% sesuai Master Data UPT Resor Sintelis 1.21 BOO).
  - Target date 8 Agustus 2025: 36 aset unik (Tim 1: 34, Tim 2: 2), tereliminasi dari 110 entri duplikat sebelumnya.
  - Global start time collisions: **0 (Zero)** across all dates and categories.
